🚨 节点测速全红 9999ms / 超时

在 Clash、v2rayN 或 Sing-box 客户端点击测速时，如果所有节点全部变红，提示 9999ms、TIMEOUT、EOF 或 i/o timeout，这说明客户端在发起握手阶段就遭遇了致命中断。

🔬 科学原理解析：客户端的“测速”到底在测什么？

很多人以为测速是客户端向目标节点发出的 ICMP Ping，其实完全不然！主流代理客户端的测速本质是：客户端首先连接本地 7890 代理端口，将一段 HTTP GET 请求发给节点，再由节点向海外测速靶场（默认通常为 http://www.gstatic.com/generate_204 或 http://cp.cloudflare.com/generate_204）发起请求，当本地收到第一个 HTTP 204 返回报文的时间差，才被计算为“延迟”。
因此，一旦本地代理端口没通、DNS 污染了节点中继域名、或者延迟测试的目标 URL 本身在国内被阻断，就会导致测速“满盘皆红”。

常见原因与深度排查实操：

原因 A
本地代理核心崩溃或本地监听端口被占用 (ECONNREFUSED)
虽然客户端界面开启了，但后台的 Clash-Meta 或 Xray 内核可能因配置解析错误、端口冲突（如 7890/10808 端口被其他软件抢占）而悄然崩溃退出。
PowerShell - 端口监听检测
PS C:\> netstat -ano | findstr :7890 # 预期输出必须包含 LISTENING 状态： TCP 127.0.0.1:7890 0.0.0.0:0 LISTENING 14820
解决方案：如果在终端运行上述命令没有任何回显，说明本地核心未启动。请在客户端设置中将 Mixed Port 改为其他未被占用的端口（例如 7898 或 17890），然后重新启动内核。
原因 B
国内中继入口域名遭遇本地运营商 DNS 污染 (Bogon IP)
许多优质专线机场的中继入口为域名格式（如 sz-entry01.relaynode.cc）。如果你的电脑使用了当地广电/小宽带提供的有毒 DNS，该域名会被解析为 127.0.0.1 或不可达的保留地址，导致客户端无法连上入口。
CMD / PowerShell - 刷新并重置系统 DNS 缓存
PS C:\> ipconfig /flushdns 已成功刷新 DNS 解析缓存。
解决方案：建议在网卡属性中将 IPv4 DNS 手动指定为国内公信力顶级 DNS：223.5.5.5（阿里 DNS）或 119.29.29.29（腾讯 DNSPod）。
原因 C
延迟测试目标 URL 本身被阻断
如果配置文件中的测试 URL 设置为 Google 的 http://www.gstatic.com/generate_204，在直连环境下拉取测试时由于国内连不上 Google，也会显示全红。

解决方案：在 Clash 设置中将 Test URL 更换为国内直连也通畅的海外 CDN 探针，例如：
• http://cp.cloudflare.com/generate_204
• http://www.msftconnecttest.com/connecttest.txt

💡 进阶验证：使用内置终端测试中继连通性

打开 PowerShell，使用 Test-NetConnection -ComputerName 节点服务器地址 -Port 端口，若 TcpTestSucceeded : True 则表示底层网络畅通。如果显示 False，说明该节点入口当前正遭受阻断或机房故障，建议在 机场状态监测 查看大盘通告，或临时切换至备用机场。

⏰ 系统时间不同步导致握手失败

在所有科学上网故障中，系统时间偏差是导致“明明节点在线、测速正常，但任何网页都打不开”的头号杀手。很多用户重装了系统、换了 3 个客户端都无法解决，最后发现仅仅是电脑慢了 70 秒。

🔐 为什么差几十秒会导致握手彻底失败？密码学底层揭秘
现代代理协议（包括 VMess、VLESS Reality、Shadowsocks-2022、Hysteria 2、TUIC）高度注重通信隐蔽性与抗审查能力：
  • 防重放攻击机制（Replay Protection）：以 VMess 协议为例，客户端发出的认证请求头中包含基于系统当前 UNIX 时间戳生成的 16 字节哈希值。服务端只接受时间误差在 ±90 秒以内（部分严苛服务端设置为 ±30 秒）的请求。超出该时间窗口的数据包，服务端会判定为黑客的恶意重放攻击并直接无视抛弃（Drop）！
  • X.509 数字证书有效窗口（TLS Handshake）：TLS 1.3 握手时，客户端校验服务端证书的 notBefore 和 notAfter 绝对时间。若本地时间漂移到证书颁发前或过期后，浏览器直接抛出 NET::ERR_CERT_DATE_INVALID 强行熔断连接。

为什么 Windows 点击“立即同步”总是提示超时？

Windows 默认的 NTP 授时服务器是 time.windows.com，由于该服务器位于微软美国数据中心，在中国大陆地区有极高的丢包率和超时阻断。因此必须将其更换为中国国内的权威顶级 NTP 服务器（如阿里云或国家授时中心）。

管理员 PowerShell - 一键配置阿里/国家授时中心 NTP 并强制对时
# 请以管理员权限运行 PowerShell，复制执行以下命令： PS C:\> w32tm /config /manualpeerlist:"ntp.aliyun.com,0x1 ntp.ntsc.ac.cn,0x1" /syncfromflags:manual /reliable:YES /update PS C:\> Restart-Service w32time PS C:\> w32tm /resync /force 正在将同步命令发送到本地计算机... 命令成功完成。
操作系统平台 图形界面设置路径 核心校验标准
Windows 10 / 11 按 Win + I 打开设置 → 时间和语言 → 日期和时间 → 开启“自动设置时间”并点击“立即同步”。 与标准北京时间差 < 5 秒
macOS 苹果电脑 系统设置 → 通用 → 日期与时间 → 开启“自动设置时间和日期”，时间服务器输入 time.apple.com。 自动 NTP 网络校对
iOS / iPhone 设置 → 通用 → 日期与时间 → 开启“自动设置”（需保持蜂窝数据连接通畅）。 基站自动广播校时
Android 安卓手机 设置 → 系统设置 → 日期和时间 → 开启“使用网络提供的时间”与“使用网络提供的时区”。 NITZ 运营商同步
⚠️ 硬件故障警示：主板 CMOS 纽扣电池掉电

若台式电脑每次开机后系统时间都会回退至 2020 年或主板出厂年份，说明电脑主板上的 CR2032 纽扣电池已耗尽电量，导致断电后 RTC 时钟停走。更换一颗 5 元的 CR2032 电池即可彻底绝除此类故障。

🔄 订阅链接无法更新与拉取失败

在客户端中点击“更新订阅（Update Subscription）”，频繁弹出 Network Error、Failed to fetch、403 Forbidden 或 SSL Handshake Failed。这是用户最头疼的“断网死锁问题”——没有节点就没法更新订阅，无法更新订阅就获取不到新节点。

故障报错特征 底层根因分析 核心解法
403 Forbidden / Cloudflare 5秒盾 机场开启了 Cloudflare 防火墙，Clash 默认 UA 被识别为恶意爬虫直接拦截。 在客户端设置中伪装 User-Agent 为标准浏览器或主流软件。
Network Error / Connect ECONNREFUSED 订阅分发域名在国内直连环境下遭到 GFW DNS 污染或 SNI 阻断。 开启客户端的“使用代理更新订阅”，借用现有节点更新。
SSL Handshake Failed / Self Signed Cert 自建转换器证书链不完整，或系统根证书证书库缺失权威 CA。 在订阅配置项中临时勾选“跳过证书验证 (Skip Cert Verify)”。
Empty Config / Invalid YAML 订阅节点已被机场后台全部禁用，或转换器接口返回了 HTML 错误页。 登录官网查看账户是否欠费，重新复制最新 Base64/Clash 专用链接。

实用破局方案：

方法 1：双通道更新法则（通过代理更新 vs 直连更新）
许多客户端（如 Clash Verge Rev、v2rayN）默认会在直连环境下请求订阅。如果机场的分发服务器部署在海外，就会被拦截。

• 如果当前还有可用节点：请在软件设置中打开“更新订阅时使用系统代理”，让流量经过现有梯子绕开封锁拉取配置。
• 如果当前所有节点都已阵亡：切断系统代理，打开手机热点连接电脑，尝试登录机场官网重新获取无污染直连备用分发域名。

方法 2：修改 User-Agent 绕过 Cloudflare WAF 质询
许多机场前端受到 DDoS 攻击后会开启 Cloudflare Turnstile 质询盾。由于内置爬虫缺少完整 JS 渲染引擎，会导致 403 报错。

在 Clash Verge 的“订阅设置”或订阅 URL 末尾添加参数，或者在全局应用设置中将 User-Agent 修改为：
clash-verge/v1.7.5 或 Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36

方法 3：手动导入离线 YAML 配置文件（保底绝招）
当客户端由于网络环境死活拉取不了订阅时：直接用电脑浏览器（或者手机浏览器）访问订阅链接。浏览器通常能正常下载或展示 YAML 文本内容。将其保存为 config.yaml 文件，然后在客户端中选择“本地文件导入 (Import Local File)”，即可 100% 绕开拉取失败。

🔌 退出代理后电脑彻底断网修复

这是广大用户最为恐慌的高频问题：“我刚刚关闭了 Clash 或 v2rayN，结果发现电脑连百度都打不开了，微信也不断提示重连，我是不是把电脑网卡烧了？”

👻 核心原理解密：“幽灵系统代理”（Ghost Proxy）是怎么产生的？

Windows 的系统代理机制基于 WinINet (Windows Internet Settings)。当你在客户端勾选“系统代理”时，软件会向注册表写入指令：
ProxyEnable = 1 并绑定 ProxyServer = 127.0.0.1:7890。
这告诉全系统所有的浏览器和应用：“发送任何网络流量，必须先丢给本地 127.0.0.1 的 7890 端口！”
正常退出软件时，软件会负责把 ProxyEnable 复位修改回 0。但如果客户端遭遇了程序崩溃、电脑睡眠唤醒、任务管理器强杀、或者在未取消系统代理前就直接点击了“退出”，注册表键值依然停留在 1！
此时 7890 端口上根本没有软件在工作，所有网页的 TCP SYN 握手请求丢向 127.0.0.1 会立即收到内核的 RST 拒绝包，从而造成整机“假死断网”。

3 种秒级复活手段：

方案 A · 5秒极速命令
运行一键注册表重置命令（无需打开任何设置）
按键盘快捷键 Win + R 打开运行窗口，输入 cmd 回车，然后复制粘贴以下命令回车：
CMD / 批处理 - 强制关闭 WinINet 与 WinHTTP 代理残留
C:\> reg add "HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings" /v ProxyEnable /t REG_DWORD /d 0 /f C:\> netsh winhttp reset proxy 操作成功完成。当前 WinHTTP 代理设置：直接访问(无代理服务器)。
方案 B · 界面操作
手动在 Windows 系统设置中关闭代理
1. 按 Win + I 打开 Windows 设置。
2. 点击 “网络和 Internet” → “代理”。
3. 找到“手动设置代理”，将“使用代理服务器”开关由“开”拨动为“关”，并点击保存。
4. 刷新浏览器网页，网络立即瞬间满血复活。
方案 C · 客户端反向重置
重新打开 Clash 走一次“开 - 关”循环
如果不习惯敲命令或找设置：直接重新双击运行 Clash Verge 或 v2rayN，在控制面板中重新勾选“系统代理”，等待 2 秒钟，然后再次手动取消勾选“系统代理”。客户端会主动调用 Win32 API 规范地清理残留键值。

🛡️ TUN 虚拟网卡安装与冲突解决

系统代理（System Proxy）虽然简单，但它有个致命缺陷：只能接管遵循 WinINet 的浏览器，对终端命令行（CMD / PowerShell / Git Clone）、网络联机游戏、WSL2、Docker、Discord 等软件完全无效。想要让全系统所有程序 100% 强制走代理，就必须启用 TUN 虚拟网卡模式。但 TUN 模式也伴随着驱动失败与路由冲突。

对比维度 普通系统代理 (System Proxy) TUN 虚拟网卡模式 (TUN Mode)
协议栈层级 OSI 第 7 层 / 应用层 (HTTP / Socks5) OSI 第 3 层 / 网络层 (IP Packet)
应用接管能力 仅限于 Chrome/Edge 等主动读取系统代理的软件 全平台无死角接管 (终端/Git/游戏/Node/Python)
UDP 数据包转发 不支持或需二次封装 完全原生支持 (适合语音与联机游戏)
驱动依赖与权限 普通用户权限即可运行 必须依赖管理员权限与 Wintun 驱动

TUN 模式 4 大典型报错与专业解决：

1. Wintun 驱动安装失败 / 提示 `Failed to create TUN device`
底层根因：Wintun 是由知名开源项目 WireGuard 打造的高性能 Windows 网络驱动。如果在首次开启 TUN 时未赋予管理员权限，或者被 360 安全卫士、火绒、Windows Defender 拦截了驱动注入，就会创建网卡失败。

解决方案：
• 右键客户端快捷方式，务必选择“以管理员身份运行”。
• 在客户端的“服务模式 (Service Mode)”中点击 Install，成功后图标会变为绿色启用状态。

2. 开启 TUN 后瞬间全机断网：路由回环死锁 (Loopback Deadlock)
底层根因：这是最危险的网络风暴——TUN 网卡接管了全局路由，却把代理客户端连接机场节点入口的外网流量也打包丢进了 TUN 网卡自身，导致数据包在虚拟网卡和物理网卡之间无限循环吞吐，瞬间占满 CPU 并造成断网死锁。

解决方案：检查配置文件中的 TUN 模块设置，务必确保开启了 严格路由 (Strict Route) 与 自动绕过直连环路 (auto-detect-interface: true)：

YAML 规范配置示例 - Clash Meta TUN 模块
# 推荐的防御路由回环 TUN 配置项： tun: enable: true stack: mixed # system / gvisor / mixed auto-route: true # 自动设置全局路由 auto-detect-interface: true # 核心：自动探测物理出站网卡，防止回环死锁 dns-hijack: - any:53 # 拦截 53 端口 DNS 查询，杜绝污染与泄漏
3. 与 WSL2、Hyper-V 或反作弊软件 (Valorant Vanguard) 冲突
底层根因：某些虚拟交换机（vEthernet）或带有内核级驱动的游戏反作弊程序会篡改网络驱动栈，导致 Wintun 抛出设备忙错误。

解决方案：
• 在 PowerShell 中运行 Get-NetAdapter 查看当前所有虚拟适配器，禁用不用的旧版本 TAP 网卡。
• 游戏对局期间建议关闭 TUN 模式，切回常规“系统代理”或使用游戏自带的专线加速器。

💡 总结：构建稳健不倒的科学上网工作流

掌握了上述 6 大核心机制后，遇到网络问题便可泰然自若。日常使用中建议：优先使用 Clash Verge Rev 或 Sing-box 的规则分流模式；遇打不开命令行或特殊软件时开启 TUN 模式；万一意外断网随手执行一条 注册表清零命令。同时，推荐在 机场深度评测 与 机场参数对比 中挑选 1~2 家具有多地 BGP 入口的优质专线作为主备冗余。
